# コーディングルール
コードを書くときは、常に保守しやすい設計、コードの共通化、変更のしやすさ、型安全を心がけること。anyはどうしようもない場合を除いて極力使わない。

# チャットに関して
チャットの回答は日本語で出力すること。
単に「調査して」と依頼された場合や、単純な質問への回答が求められた場合は、いかなる場合であっても、「プログラムの修正」や「ファイル内容の変更」、「解決するためのPlanの作成」を行ってはならない。
また、「調査」やそれのみを目的とする質問に対しては、バグが見つかったとしても原因究明にとどめ解決策を提示してはならない。

# 時刻・時間の取り扱い
プログラム内で時刻を扱う際は、常に「ローカル時間」の存在を意識し、実行環境やユーザーのタイムゾーンによって値が変動する可能性を十分に考慮すること。無意識な実装による意図しない挙動を防ぐため、常に細心の注意を払って設計・実装を行うこと。

# コンパイルチェック
プログラム変更後一段落したら必ず「npx tsc --noEmit」を実行して、コンパイルエラーがないか確認すること。エラー修正が終わった後も再度「npx tsc --noEmit」を実行して、エラーが無ければ、なにを変更したのか"日本語で"まとめてチャットに出力して。
