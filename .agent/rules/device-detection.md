# デバイス判別およびUI設計ルール

本アプリは**スマートフォン（モバイルデバイス）での利用を第一に想定**して設計する。PCでの閲覧時であっても、モバイルライアウトを基本とする。

## 1. UI・デザインの基本方針
- **モバイルファースト**: レイアウトは常にスマホでの操作性を最優先する。
- **ホバー要素の除外**: モバイル端末ではホバー操作ができないため、ホバーによる情報の表示（ツールチップ等）や、ホバーアニメーション、ホバー時のスタイル変更は原則として実装しない。
- **タップしやすさ**: ボタンやインタラクティブな要素は、指でタップしやすいサイズと余白を確保する。

## 2. デバイス判別の使い分け
以下の2つの方法を、用途に合わせて適切に使い分ける。

### A. 機能・操作ベースの判別（推奨）
ブラウザの「精密なポインタ（マウス等）」および「ホバー」の有無に基づいて判定する。操作体験に直接依存する機能の制御に使用する。

- **使用方法**: `useDevice()` フック（`DeviceContext`）を使用する。
- **判定基準**: `(pointer: fine)` かつ `(hover: hover)` であれば `isComputer: true` と判定される。
- **参照**: [DeviceContext.tsx]
- **主な用途**: モバイル環境限定のボタン表示（貼り付けボタンなど）、ドラッグ＆ドロップの代替手段の提供など。

### B. レイアウト・画面幅ベースの判別
Material UI のブレークポイント（画面横幅）に基づいて判定する。UIのレスポンシブな配置調整に使用する。

- **使用方法**: `useMediaQuery(theme.breakpoints.down('sm'))` など。
- **判定基準**: `sm` (600px) 以下であればモバイルレイアウトと見なす。
- **主な用途**: ダイアログの全画面化、余白の調整、要素の積み上げ（Stack）順の変更など。
